## 1. 从对比分析里带过来的五条结论

1. 中文站 `shuxuele.com` 只是「翻译到 2020 年的一半成品」（完整度约 53%，评分 ≈42/100），不能作为复刻目标。
2. MathsIsFun 全站 `© Rod Pierce`，隐私页的「free」只是「访客免费」，**1:1 复刻＝侵权**，不做。
3. 值得做的是**路线 C：重写交互组件库**——实测全站强交互单元 250–400 个，基础原语约 20 个；做完原语，80% 页面只是填参数。
4. AI 可以承担 95% 的代码与生产，但**「答案对不对」必须机器验算**；数学站的优势是可以用程序自证。
5. 永远由人负责的四件事：账号注册、域名备案、按下发布、错误责任。

## 2. 本次 MVP 做什么（只做两条线）

### A. sympy 审核闸（最小可用）

目标：**内容里的每个数字，都能被机器算一遍；算不对就不许构建。**

- 在命题 Markdown 的 frontmatter 里增加 `checks:` 字段，声明可验算的断言；
- `web/scripts/math_gate.py` 用 sympy 逐条复算，输出通过/失败清单；
- `npm run build` 先跑审核闸（与 `check-ledger` 并列），失败即中断；
- 覆盖现有 9 个命题的关键结论（人数、物价、面积、比例、开方、体积、追及、方程解、配分）。

支持两种断言：

```yaml
checks:
  - label: 人数          # 给人看的名字
    solve: "8*n - 3 = 7*n + 4"   # 解方程
    for: n                        # 未知数
    expect: "7"                   # sympy 表达式，可为分数 37/4
  - label: 物价
    value: "8*7 - 3"             # 直接求值
    expect: "53"
```

### B. lab 组件库（6 个基础组件）

目标：**证明「原语 + 填参数」这条路能跑**，不是再造 9 个一次性页面。

| # | 组件 | 能力 | 用在哪些题 |
|---|---|---|---|
| 1 | `CoordPlane` 坐标系 | 网格 + 坐标轴 + 点击/拖动取点 | 盈不足、粟米、均输 |
| 2 | `SliderControl` 滑块 | 拖动取值 + 实时读数 + 公式回显 | 全站 |
| 3 | `DragPoint` 拖拽点 | 网格吸附、键盘方向键、坐标回显 | 勾股、方田 |
| 4 | `NumberLine` 数轴 | 吸附刻度、负数、分数刻度 | 盈不足、方程 |
| 5 | `FractionBar` 分数条 | 双条对比、份数着色、谁大谁小 | 衰分、粟米 |
| 6 | `Protractor` 量角器 | 拖射线、5° 吸附、角度回显 | 几何原本、勾股 |

统一要求：

- 纯 SVG/DOM + Pointer Events，不引入新依赖；
- 鼠标、触屏、键盘（方向键）都能操作；
- 每个组件一个 `.astro` 文件，样式统一在 `web/src/styles/lab.css`；
- 实验台页面 `/lab` 同时展示 6 个原语 + 3 个组合演示（勾股、面积、分数）。

## 3. 验收标准（达不到就不算完成）

1. `npm run check:math` 输出 9 个命题全部通过；故意改错一个数字能失败并指出位置。
2. `npm run build` 在审核闸失败时中断。
3. `/lab` 页面 6 个组件都能拖、能按键、手机宽度不横向滚动。
4. 3 个组合演示只靠原语拼装，没有新增一次性代码。
5. 不引入新的运行时依赖；不接广告、不接追踪脚本。

## 4. 明确不做

- 不做 2,915 页全站复刻，不抄 MathsIsFun 的文案、图片、代码；
- 不做 20 个原语，本次只做 6 个；
- 不做自动内容生成流水线（选题、白话生成），本次只做「验算闸」；
- 不做账号、后端、数据库、App。

## 5. 后续路线（本次验收通过后再谈）

| 阶段 | 内容 | 判据 |
|---|---|---|
| L1（本次） | 6 原语 + 3 组合页 + 审核闸 | 构建通过、真机能玩 |
| L2 | 补到 20 原语 + 30 个组合页 | 新增页面 80% 只填参数 |
| L3 | 50 页精选（覆盖勾股/面积/分数/百分比/一次函数） | 自然搜索有起色 |
| L4 | AI 生产 + 审核闸 + 每周 20 分钟抽检 | 单页成本降到人工的 1/5 |

## 6. 风险

| 风险 | 对策 |
|---|---|
| 审核闸只验数字，验不了「讲得好不好懂」 | 白话仍走外部审校；闸只当质检员，不当老师 |
| 组件越做越像一次性页面 | 新页面必须先问「能不能用 6 个原语拼」 |
| `checks` 与正文脱节 | 每条 check 的 label 必须能在正文里找到对应结论 |
| 触屏体验照抄桌面悬停 | 所有交互只用 pointer 事件，键盘可替代 |

## 7. 主题线（`/topics`）：把「数学乐式页面」跑通

> 2026-10-27 起实施。**只复刻形态，不搬内容**：页面结构（概念 → 交互 → 例子 → 练习）学数学乐，
> 文字、例子、练习全部自编；红线仍是不翻译、不镜像 mathsisfun.com / shuxuele.com。

- 路由：`/topics/` 列表（按「数 / 代数 / 几何 / 数据」分类）+ `/topics/<id>/` 详情。
- 每页固定四段：**一句话定义 → 先动手看看 → 讲解 + 例子 → 两道练习**，底部注明自编与勘误入口。
- 内容模型：`src/content/topics/*.md`，frontmatter 带 `examples` / `exercises` / `checks`；
  `checks` 与命题共用同一道 sympy 审核闸（`math_gate.py` 已同时扫描两个目录）。
- 交互复用 lab 原语：`CoordPlane`（勾股）、`FractionBar`（分数）、`NumberLine`（百分比），
  组合层只写「读数换算」的胶水组件。

### 7.1 全站体系（2026-10-27 一次建全）

目录不按「想到哪做到哪」长，而是先按已验证的「大类 → 章节 → 主题」三层建满，再逐页填内容：

| 项 | 数量 |
|---|---|
| 大类 | 6（数与运算 / 代数 / 几何 / 测量 / 数据与概率 / 数学活动） |
| 章节 | 23 |
| 主题路由 | 104（全部可访问，含 3 个已写完） |
| 构建页面 | 127 |

- 唯一真源：`web/src/data/curriculum.ts`；新增主题只改这一个文件，路由、导航、搜索、章节页自动生成。
- 三种页面同一套模板：`/topics/`（体系总览 + 搜索）、`/topics/<大类>/`（章节目录）、
  `/topics/<大类>/<主题>/`（已写完 → 正文 + 交互 + 例子 + 练习；未写完 → 说明 + 同章目录 + 上下篇）。
- 状态即数据：有 Markdown 就是「已完成」（`●`），没有就是「编写中」（`○`），页面上直接可见进度条。
- 首发批次是**先横后纵**：先把 6 大类全部跑通，再在每类里挑高频主题填内容，避免出现「只有一个分类能用」。
