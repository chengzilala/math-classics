## 1. 定位

**一句话**：用公有领域的中国古代数学经典，做「原文 → 白话 → 动手做 → 小练习」的趣味交互学习站。

**目标用户**（按优先级）：

1. 对数学好奇、但被教材劝退的成年人（碎片时间，手机 + 桌面）
2. 想给孩子讲点「中国古人怎么算」的家长
3. 中学老师 / 数学爱好者（找素材、找可视化）

**用户为什么来**：不是来刷题，是来**看懂一个古人解决过的真问题**，并且能自己动手把答案拖出来。

**成功的样子**：随机给一个普通人看 3 分钟，他能说出「哦，原来盈不足是这个意思」。

## 2. MVP 范围

### 做

- 内容线按书分栏目，同站不拆站；**首页只做门户，不堆题目**：
  - **九章算术线**：9 个命题，九卷各取一题：方田（面积）、粟米（比例）、衰分（配分）、少广（开方）、商功（体积）、均输（追及）、盈不足（双假设）、方程（线性方程组）、勾股
  - **孙子算经线**：第 1 题取鸡兔同笼（卷下第 31 题，半足术）
  - **趣味数学线**：按「图解 + 小实验 + 练习」原创，不复制、不翻译；内容即 `/topics/` 课程体系（6 大类 / 23 章 / 104 个主题路由），已写完 3 个，其余标「编写中」
- 首页是三栏目门户：英雄区 + 三张栏目卡 + 本机进度 + 读法 + 关于；三张卡分别进入 `/jiuzhang/`、`/sunzi/`、`/fun/`
- 命题页 URL 保持 `/propositions/<id>/` 不变；每条线一个栏目页，题目卡只在栏目页出现
- 每命题一页，完整 5 段结构
- 交互作图（JSXGraph），鼠标 + 触屏都可用
- 本地进度（localStorage）；**可选登录统一账户中心**（只借身份，不自建账号，不登录也能做题）
- 出处 + 勘误入口

### 不做（MVP 明确排除）

- App / 小程序 / 后端 API / 自有账号体系（登录只接统一账户中心，不自建） / 支付
- 广告 / 第三方统计脚本
- 几何原本（作为第 2 阶段内容线）
- 用户生成内容、社区、评论
- 多语言

## 4. 详细需求

### F1 页面骨架

- 首页：站名 + 一句话介绍 + 三张内容线栏目卡 + 本机进度条；点进栏目页再看具体题目。
  > 2026-10-27：九题全部上线，首页曾用三列三行的命题卡保持一屏吸附。2026-10-28：改为三栏目门户，命题卡移入各栏目页。
- 首页是三栏目门户：英雄区（站名 + 一句介绍 + 题目/内容线/时长三个数 + 两个按钮 + 勾股循环作图）；下方三张栏目卡（编号、拉丁名、书名、一句简介、题数或「筹备中」、进入栏目），再下面是本机进度、读法四步、关于与勘误入口。首页**不列具体题目**。
- 内容线栏目页 `/jiuzhang/`、`/sunzi/`、`/fun/`：书名 + 一句简介 + 数量 + 卡片（章节/分类、标题、摘要）+ 线间导航；`fun` 按课程体系列 6 个大类（各带章节数 / 主题数 / 已写完数），点进 `/topics/<section>/`；没有任何内容时才显示「筹备中」面板，不编造内容。
- 题目卡只出现在栏目页；首页旧的按书分组、悬停预览不再使用（栏目页卡片直接铺摘要）。
- 命题页：固定 5 段结构，锚点导航（桌面右侧目录，手机顶部折叠）。
- 关于页：这是什么东西、内容来源原则、勘误方式、许可说明。

### F2 内容模型

每个命题一份 Markdown（frontmatter + 正文），字段至少包含：

```yaml
id: jiuzhang-yingbuzu
title: 盈不足
line: 九章算术
chapter: 卷七 · 盈不足 · 第一问
summary: 一句话摘要（首页卡片用）
significance: 数学意义（首页悬停浮层用）
related:                # 引用命题（首页悬停浮层，可空）
  - label: 粟米 · 同用比例
    id: jiuzhang-sumi
source: 维基文库《九章算术》卷七
source_license: 公有领域
original: |            # 原文，简体照录
  今有共买物，人出八，盈三；人出七，不足四。问人数、物价各几何？
original_note: 可选，说明原文取舍（如术文暂未录）
steps:                  # 白话 3 步，固定 3 条
  - text: 第一步…        # 每步不超过 60 字
    analogy: 可选的生活类比
interaction: yingbuzu-line   # 对应的交互组件 id
exercises:              # 3 题：认概念 / 算一算 / 换个数字
  - kind: concept
    question: …
    options: [ … ]
    answer: 0           # 正确项下标
    hint: 答错时的提示
    note: 答对后的「古人怎么说」
proofreader: 待定
checks:                 # 机器验算断言（构建前由 sympy 复算，至少 1 条）
  - label: 人数
    solve: "8*n - 3 = 7*n + 4"
    for: n
    expect: "7"
  - label: 物价
    value: "8*7 - 3"
    expect: "53"
updated: "2026-10-25"   # 必须加引号，否则被 YAML 解析成日期
order: 1                # 首页排序
```

**规则**：内容与视图分离；组件不写死任何原文；未填 `source` 的命题**不允许构建**。

### F3 原文 + 白话

- 原文直接展示，不做折叠；原文统一用简体字照录，竖排/横排由内容决定，不强制仿古排版。
- 白话固定 3 步，每步一句话 + 一个生活类比，**每步不超过 60 字**。
- 术语第一次出现时给一句话解释（不用弹窗，用脚注样式）。

### F4 交互作图（核心）

每个命题至少 1 个「拖动就能看见关系」的任务，例如：

| 命题 | 交互任务 | 学到的点 |
|---|---|---|
| 盈不足 | 拖动「每人出多少」，看盈余/不足两条线交点 | 双假设法的几何意义 |
| 方田 | 拖动长宽，看面积与「步」的换算 | 面积=长×宽，单位换算 |
| 粟米 | 拖动粟的斗数，看粜米的比例变化 | 比例与「今有术」 |
| 勾股 | 拖动直角边，看勾股弦关系与「三五四五」 | 勾股定理的数值感受 |

**验收要求**：拖动时数值实时更新；有「复位」按钮；触屏可拖；不依赖网络资源。

### F5 小练习

- 每命题 3 题：1 题「认概念」、1 题「算一算」、1 题「换个数还能用吗」。
- 答错给提示，不给答案；答对给一句「古人怎么说的」。
- 不做错题本、不做积分排行。

### F6 进度

- localStorage 键：`mc:progress:v1`，值为 `{ "<命题id>": { done: true, at: "ISO日期" } }`。
- 首页进度条 + 卡片角标；提供「清空进度」按钮。

### F7 出处与勘误

- 每页底部必须显示：书名 / 卷或题号 / 底本 / 许可 / 校对人 / 最后更新。
- 勘误入口：一个 `mailto:` 或 GitHub Issue 链接，二选一（发布前定）。
- **未登记 `plan/版权台账.csv` 的命题不得进入构建。**

### F8 SEO / 分享

- 每页 `<title>`、`description`、`og:image`（自绘 SVG 转 PNG）。
- 生成 `sitemap.xml`、`robots.txt`。
- 站名：**算经小课**（2026-10-28 定）。「算经」承《算经十书》脉络，「小课」点明「一课三分钟」的形态，避免单用「算经」被古籍词淹没。
- 标题写法按搜索习惯「需求词前置 + 品牌后缀」：首页 `《九章算术》白话图解，3 分钟看懂一道古题`；命题页 `{题名}是什么意思？《{书名}》白话图解`；品牌由 `Base.astro` 统一追加 `· 算经小课`，整条控制在 30 字内。

### F9 响应式

- 断点：`< 640px`（手机）、`640–1024px`（平板）、`> 1024px`（桌面）。
- 手机：单列，画布宽度 100%，高度自适应，交互控件不小于 44px。

## 5. UI / UX 约定

- **气质**：墨蓝 + 金线。深墨蓝底、米金正文、金色作强调；参考 `https://jihe.1mi.ai` 的视觉方向（2026-10-26 用户指定），但配色、版式、图形与文案全部自绘，不搬对方代码和素材。
- 字体：标题用**宋体 / 思源宋体**，正文用系统黑体保证可读；只用系统字体与 OFL 授权字体。
- 颜色：底色 `#070b16` / 面板 `#0d1426`，正文 `#ece6d6`，次要文字 `#8d95a9`，金色强调 `#d9b25f`，辅助蓝 `#6aa8ff`。
- 版式：固定顶栏 + 巨幅渐变标题 + 细分隔线 + 编号清单；命题页保留 5 段结构与右侧目录。
- **首页版式（2026-10-27 定稿）**：全宽 46% / 54% 双栏。左栏是 `position: sticky` 舞台；首屏只展示「算经」主体（巨幅流光宋体标题 + 副标 + 一句说明）与竖向圆点分区导航、底部「序号 — 分区名 / 向下滚动」；右栏四段：起点 / 命题 / 读法 / 开始，每段 `min-height: 100vh`。
- **整段吸附**：桌面（宽 ≥ 960px 且高 ≥ 700px）`html` 开 `scroll-snap-type: y mandatory`，每段 `scroll-snap-align: start` —— 每次下滑整屏落到下一段，左栏舞台不动。
- **左栏连续作图（2026-10-28 定稿，替代「随滚动换图」；同日改为滚动联动）**：首屏左栏只留「算经」主体；向下滑到第二段起，标题淡出收起，左栏改为一块勾股作图——直尺画股（四）→ 画勾（三）→ 连弦（五）→ 圆规以弦为直径作圆（直角自现）→ 标出「九 + 十六 = 二十五」，六拍。**进度只由右栏滚动位置决定**（滚到第几段就画到第几拍，缓动追上，避免整段吸附时一顿一跳），不单独计时、不自动循环，左右同一步调；最后一屏停在完整图形。按住左右拖动可临时回看任意一拍，松手后由下一次滚动接管；图下「01 / 06 + 六格拍点」随进度点亮。装饰性（`aria-hidden`），`prefers-reduced-motion` 下只显示完整图形、不跟滚动。
- **矮屏**（高 ≤ 820px）压缩段内间距与卡片高度，保证每段仍能一屏放完；**≤ 959px** 退化为单列（舞台在顶部、不吸附、隐藏装饰线描与场景图）。
- **命题页全宽（2026-10-27 定稿）**：命题页与首页一样铺满视口（`main` 不再限 1120px）。桌面 ≥ 1024px 时，页头拆成左右两栏（左：卷次 + 巨幅标题；右：摘要，底对齐）；正文列占满剩余宽度，右侧目录贴最右；分区标题与分隔线横跨整屏，正文块最大 70rem 保证可读行长。
- **练习选项自适应（2026-10-27 定稿）**：选项按钮不再固定单列拉满整行，按可用宽度自动排布（`repeat(auto-fit, minmax(min(100%, 15rem), 1fr))`）——手机 1 列、平板 2 列、桌面 3–4 列，按钮最小高度仍 44px。
- 顶栏导航 4 项：起点 / 命题 / 读法 / 关于；首页按当前分区高亮，内页按路由高亮。
- CSS 类名统一前缀 `mc-`。
- 动效：只允许「渐变 / 线条描绘 / 数值平滑」三类，禁止弹跳、旋转、闪烁；`prefers-reduced-motion` 下全部关闭。
- 无障碍：正文对比度 ≥ 4.5:1；交互控件有 `aria-label`；键盘可操作。

## 6. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Astro + TypeScript | 内容站，默认零 JS，按需水合 |
| 内容 | Markdown + frontmatter（Astro Content Collections） | 数据与视图分离，天然可校验 |
| 交互 | JSXGraph（MIT / LGPL-3.0） | 可商用、体积小、几何/函数都能画 |
| 公式 | KaTeX | 服务端渲染，无闪烁 |
| 样式 | 原生 CSS + CSS 变量 | 不引框架，避免长期维护负担 |
| 状态 | localStorage | 零后端、零隐私风险 |
| 部署 | **腾讯云轻量 + Caddy**（`math.chesterlee.cn`） | 与全站统一，走 `部署上线备案/README.md` 的 5 步；不走 Cloudflare Pages |
| 统计 | Cloudflare Web Analytics（无 Cookie） | 合规，不接 GA |
| 数值审核 | sympy 1.14（Python 3.13 + PyYAML） | 内容里的数字在构建前机器复算，算错就断构建 |

**目录规划（第 1 阶段已建成）**：

```
web/
├── src/
│   ├── content/propositions/<命题>.md   # 一题一份，全部字段在 frontmatter
│   ├── components/       # 交互组件、练习组件
│   ├── layouts/Base.astro
│   ├── pages/            # 首页（含「关于」滚动段）/ propositions/[slug]
│   ├── styles/           # global.css + JSXGraph 基础样式
│   ├── content.config.ts # 内容模型（zod 校验）
│   └── site.ts           # 站名、勘误入口
├── scripts/check-ledger.mjs  # 构建前校验版权台账
├── public/               # favicon 等原样复制资源
├── astro.config.mjs
└── dist/                 # 构建产物（不入库）
```

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 白话写错 / 讲偏 | 误导用户，损害可信度 | 双源核验 + 外部审校 + 公开勘误；宁少做不多做 |
| 用错底本（误用现代点校本） | 侵权 | 版权台账逐个登记；只用维基文库/影印件 |
| 交互太重、手机卡 | 体验差 | 每页只画一个图；JSXGraph 按需加载 |
| 范围膨胀（想加账号/课程/社区） | 做不完 | 本 RPD 的「不做」清单为硬边界，新增需求另立版本 |
| 备案 / 合规 | 无法上线 | 阶段 3 前单独确认；非经营性个人站先按最小口径 |
| 没人看 | 自我怀疑 | 阶段 3 先找 20 个真人，不追流量 |
